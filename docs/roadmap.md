# Roadmap público

Este roadmap descreve etapas planejadas. Uma etapa só deve ser marcada como concluída quando houver artefatos e testes verificáveis.

## Etapa 0 — Fundação
- [x] Definir o repositório como superfície pública do produto.
- [x] Documentar princípios, limites e arquitetura conceitual.
- [ ] Definir stack e comandos reproduzíveis de desenvolvimento.
- [ ] Adicionar política de contribuição e licença após decisão explícita.

## Etapa 1 — Protótipo mínimo
- [ ] Selecionar um formulário de teste sintético.
- [ ] Definir esquema de saída versionado.
- [ ] Implementar entrada e pré-visualização do documento.
- [ ] Implementar extração inicial.
- [ ] Construir interface de revisão humana.
- [ ] Validar e exportar dados estruturados.
- [ ] Adicionar testes automatizados e dados sintéticos.

## Etapa 2 — Avaliação
- [ ] Criar protocolo de avaliação reproduzível.
- [ ] Medir qualidade por campo e por tipo de documento.
- [ ] Medir taxa e tipo de correções humanas.
- [ ] Avaliar documentos inclinados, ruído, baixa resolução e campos ausentes.
- [ ] Publicar limitações e resultados com metodologia.

## Etapa 3 — Operação controlada
- [ ] Avaliar requisitos de autenticação e autorização.
- [ ] Definir comportamento em ambientes com conectividade limitada.
- [ ] Revisar segurança, privacidade, retenção e trilha de auditoria.
- [ ] Avaliar requisitos de integração com sistemas externos, sem presumir acesso a APIs hospitalares.

## Critérios de saída

Nenhuma funcionalidade será descrita como pronta para produção apenas por existir uma demonstração. A prontidão depende de testes, documentação, revisão de segurança, validação com usuários autorizados e aprovações aplicáveis.
